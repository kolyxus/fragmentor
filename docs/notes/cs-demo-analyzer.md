# cs-demo-analyzer

Изучено 2026-11-05: исходники `github.com/akiver/cs-demo-analyzer v1.13.0` (24.10.2026) в кэше модулей — README,
`pkg/api/analyzer.go`, `player.go`, `kill.go`, `clutch.go`, `damage.go`, `faceit.go`, `match.go`, `weapon.go`,
`export_json.go`. Это анализатор CS Demo Manager. Нужен нам только для сверки метрик шага 5
(`go run ./cmd/parsedemo -csda <папка> testdata`), в модуль бота не входит.

## Версия и сборка

- Работает на demoinfocs **v4**: в `go.mod` есть `replace` на коммит форка `v4.5.2-0.20261019222625-b5a02b17ce7a`.
  Из-за `replace` команда `go install …/cmd/cli@v1.13.0` не работает, а сборка зависимостью берёт v4.5.1 без форка.
  Собирать надо как главный модуль: скопировать исходники во временную папку и запустить `go build -o csda.exe ./cmd/cli`.
  Проверить, что взят форк: `go version -m csda.exe | grep demoinfocs`.
- Читает только распакованный `.dem` по пути (`os.Open`), `.dem.zst` не понимает. Для сверки демку распаковываем
  во временную папку и удаляем сразу после прогона. Это вне бота, бот по-прежнему распаковывает потоком.

## Запуск

```
csda -demo-path=<демка>.dem -output=<папка> -format=json -source=faceit
```

- Пишет `<папка>/<имя демки без .dem>.json`, на демку 4–7 МиБ, 4–9 с. С `-positions` файл в разы больше — не нужен.
- В JSON ники и SteamID: держим вне репозитория.
- `players` — словарь по SteamID64 (ключ строкой, `steamId` числом больше 2^53: в JavaScript его не читать как число).
- `kills`, `damages`, `clutches`, `rounds` — списки событий с номером раунда; сторона: 2 — T, 3 — CT, 0 — мир.
- Типы оружия: `pistol`, `smg`, `shotgun`, `rifle`, `sniper`, `machine_gun`, `grenade` (с огнём), `equipment` (бомба),
  `melee` (нож и Zeus), `world`.

## Как считает

Раунды на наших пяти демках FACEIT совпадают с нашими: старт матча он берёт по `MatchStartedChanged`, предматчевый
раунд не попадает.

| Метрика | Как у cs-demo-analyzer | У нас |
|---|---|---|
| Убийства | без самоубийств и тимкиллов; убийства игрока под ботом не считаются | по правилам FACEIT: под ботом — игроку |
| Смерти | без выхода с сервера (самоубийство с оружием `world`); убийства в заморозке пропускает вовсе | любая смерть, как FACEIT |
| Урон | `HealthDamageTaken` v4; жертва — по контроллёру, урон по ботам не считается | снятое здоровье тела, как FACEIT |
| ADR | урон / все раунды матча | так же |
| KAST | доля **всех** раундов матча; тимкиллы, самоубийства и выходы пропускает целиком — такой раунд «выжил»; ассист засчитывает без проверки сторон, в том числе на смерть своего тиммейта | HLTV: раунды, начатые живым; выход живым — раунд не считается |
| Первое убийство | первое убийство раунда, кроме самоубийств, тимкиллов и убийств игроком под ботом | первое убийство между врагами |
| Размен | убийца жертвы сам убит в этом раунде **меньше** чем через 5 с (`>= 5` — уже нет) | не больше 5 с |
| Клатч | после каждого убийства считает живых по состоянию игры (`IsAlive`), первый 1vX и потом 1v1 другой стороны; исход ставит в `RoundEnd` | живые от конца заморозки по событиям; после конца раунда клатчей нет |
| Мультикиллы | раунды ровно с N убийствами по его правилу убийств | так же, по убийствам K |

Подводные камни:

- **Клатчи игрока в `players` неверны:** `oneVsXClutches` к клатчам игрока прибавляет все клатчи матча с тем же X
  (`player.go`). Верен только список `clutches`, по нему и сверяем.
- Клатч, начавшийся после `RoundEnd` (бомба или добивание после раунда), он заводит, а исход уже не ставит: `hasWon` = false.
- Живых считает по состоянию сущностей, которое внутри тика отстаёт: вторая жертва того же тика ещё «жива».
- Окно размена сравнивается по тикам с `>=`: ровно 5 с (320 тиков) у него уже не размен.
