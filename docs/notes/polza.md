# polza.ai в Fragmentor

Сверка 2026-11-26 по официальной документации и примерам. В шаге 8в локально проверяется только непотоковый текстовый вызов.

## Запрос и ответ

Базовый адрес API — `https://polza.ai/api/v1`. Клиент добавляет `/chat/completions` и отправляет POST с JSON и заголовком `Authorization: Bearer …`. В теле передаёт `model`, текстовые `messages`, `max_tokens` и `stream: false`. При HTTP 200 ожидает один завершённый ответ ассистента с `finish_reason: "stop"` и текстом в `choices[0].message.content`. Усечённый ответ считается ошибкой, даже если в нём есть текст. [Справочник](https://polza.ai/docs/api-reference/chat/completions) · [Примеры текстовых запросов](https://polza.ai/docs/gaidy/chat-completions).

В `usage` провайдер сообщает входные `prompt_tokens`, выходные `completion_tokens` и списанную сумму в рублях `cost_rub`. Допускается алиас `cost`. Клиент берёт его, если `cost_rub` отсутствует или равен `null`. Каждое известное значение попадает в структурированный лог, в том числе ноль и расход при отклонённом тексте. Пропущенное значение остаётся неизвестным. [Учёт средств](https://polza.ai/docs/osobennosti/usage).

## Настройки и повторы

Пакет `internal/llm` получает настройки при создании клиента. Адрес, ключ и идентификатор модели обязательны. Остальные настройки имеют значения по умолчанию.

| Переменная | Значение по умолчанию | Что ограничивает |
| --- | --- | --- |
| `LLM_TIMEOUT` | `30s` | Весь вызов, включая чтение ответа и ожидание повтора. Более ранний срок из контекста имеет приоритет. |
| `LLM_MAX_TOKENS` | `1024` | Токены генерации, передаётся в API. |
| `LLM_MAX_REQUEST_BYTES` | `65536` | Размер сериализованного JSON перед отправкой. |
| `LLM_MAX_RESPONSE_BYTES` | `1048576` | Размер читаемого тела успешного HTTP-ответа. |
| `LLM_MAX_RETRIES` | `1` | Один повтор после HTTP 429. Значение `0` отключает повтор. |

В примере polza.ai для HTTP 429 указан `Retry-After`. Fragmentor принимает секунды или HTTP-дату. При отсутствующем или неверном заголовке пауза составляет секунду. Если пауза исчерпает оставшееся время, клиент сразу возвращает HTTP 429. Другие HTTP-статусы возвращаются вызывающему коду. Таймаут, обрыв связи и HTTP 5xx могут оставить исход платного POST неизвестным. Повтор в этих случаях создавал бы риск ещё одного списания. [Пример обработки ограничений у провайдера](https://polza.ai/use-cases/seo-content).

Проверка контракта использует локальный TLS-сервер `httptest` с синтетическими сообщениями, ответами и суммами. Фактическую стоимость на выбранной модели предстоит проверить при отдельном живом прогоне владельца.
