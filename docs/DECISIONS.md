# Журнал решений

Формат: дата — решение — почему. Новые записи добавляются в конец.

- 2026-10-29 — Стек: Go и demoinfocs-golang. — Родной язык автора; библиотека зрелая, на ней работают scope.gg и HLTV.
- 2026-10-29 — Все цифры считает код, LLM только пишет текст. — Точность и защита от выдуманных чисел.
- 2026-10-29 — LLM через polza.ai, модель DeepSeek V4.1 Flash. — Оплата в рублях, разбор стоит около 10 копеек.
- 2026-10-29 — Без входа через Steam, привязка по нику FACEIT. — Данные FACEIT публичные, а вход через Steam от малоизвестного бота выглядит как фишинг.
- 2026-10-29 — До одобрения Downloads API демку берём по подписанной ссылке, которую присылает пользователь. — Официального доступа ещё нет, ссылка живёт около 5 минут, поэтому скачиваем сразу.
- 2026-10-29 — Демки не храним, в LLM отправляем только обезличенные цифры. — Так обещано на сайте и в политике конфиденциальности.
- 2026-10-29 — SQLite на старте. — Один файл, без отдельного сервера БД. Переход на Postgres — когда упрёмся.
- 2026-10-29 — Заявка на FACEIT Downloads API поставлена на паузу: FACEIT приостановил некоммерческие заявки. — Основной путь получения демок: ссылка от пользователя (шаг 7) и расширение для браузера (шаг 10). Автоматический режим отложен.
- 2026-10-29 — Go 1.27 (`go 1.27.0` в `go.mod`), разработка на 64-битной сборке Go; модуль `github.com/kolyxus/fragmentor/bot`. — Последняя стабильная версия; 32-битный Go медленнее, ограничен по памяти (важно для разбора демок) и без race-детектора.
- 2026-10-29 — Версии библиотек: `github.com/go-telegram/bot` v1.27.0, `modernc.org/sqlite` v1.61.0 (SQLite 3.54.1). — Последние на момент шага; заметки в `docs/notes/`.
- 2026-10-29 — `.env` читаем своим парсером в `internal/config`, без godotenv; переменные окружения важнее файла; в ошибках конфига только имена переменных. — Формат простой, лишняя зависимость не нужна; значения могут быть секретами.
- 2026-10-29 — SQLite: WAL, `busy_timeout` 5 с, `synchronous=NORMAL`, `foreign_keys` включены, транзакции `BEGIN IMMEDIATE`, пул до 4 соединений. Время — `INTEGER` unix-секунды UTC, таблицы `STRICT`. — Писатель не блокирует читателей, транзакции не падают на полпути с `SQLITE_BUSY`; драйвер по умолчанию пишет `time.Time` строкой с монотонными часами.
- 2026-10-29 — Миграции: файлы `internal/storage/migrations/NNNN_name.sql` без пропусков номеров, таблица `schema_migrations(version, name, applied_at)`, каждая миграция в своей транзакции; база новее бинарника — отказ стартовать. — Нельзя случайно запустить старую версию на новой схеме.
- 2026-10-29 — `users.language` хранит язык бота (`ru`/`en`), `username` — NULL, если ника нет. Повторный `/start` обновляет ник и язык, `created_at` и `joined_waitlist_at` не меняет. — Ник со временем меняется, а дата входа в очередь нужна первая.
- 2026-10-29 — Язык: `ru` и его региональные варианты — русский, всё остальное и пустой код — английский. Команды и описания регистрируются для языка по умолчанию (английский, покрывает `en` и прочие) и для `ru`; при старте меняем только отличающееся, ошибка регистрации не останавливает бота. — Правило из CLAUDE.md; частые перезапуски не должны упираться в лимиты `setMy*`.
- 2026-10-29 — Апдейты обрабатывают 4 воркера синхронно (`WithNotAsyncHandlers` + `WithWorkers`), у каждого апдейта свой таймаут 30 с вместо контекста опроса, паники перехватываются. По SIGINT/SIGTERM опрос останавливается, начатые ответы дорабатывают, потом закрывается база; второй сигнал завершает сразу. — По умолчанию библиотека не ждёт обработчиков при остановке.
- 2026-10-29 — Long polling 50 с, HTTP-клиент 60 с; прокси для Telegram — через `HTTPS_PROXY`. — У библиотеки по умолчанию запас всего 1 с; доступ к Telegram из России бывает нестабильным.
- 2026-10-29 — Бот работает только в личных чатах; на непонятные сообщения отвечает подсказкой про /start и /help. Сообщения — обычный текст без `parse_mode`, без превью ссылок. — Группы не нужны; HTML с экранированием появится на шаге 9.
- 2026-10-29 — Переключателя языка в боте не делаем, язык ответа — только по `language_code`. — Проверка на Telegram Desktop: английский приходит, когда и система, и Telegram на английском, иначе `ru`. Англоязычным пользователям это подходит, а кнопка выбора языка лишняя.
- 2026-10-29 — В логах нет Telegram ID, ников и текстов сообщений; обработчик библиотеки по умолчанию (пишет апдейт целиком) заменён. Токен в сетевых ошибках маскирует библиотека, это закреплено тестом. Исходный `language_code` пишется только на уровне debug. — Персональные данные и секреты не попадают в логи; код языка не идентифицирует человека.
- 2026-10-30 — Сервер: бинарник `/opt/fragmentor/fragmentor`, секреты `/etc/fragmentor/fragmentor.env` (root, 600) подключаются через `EnvironmentFile`, база в `/var/lib/fragmentor` (`StateDirectory`, путь задан в юните), системный пользователь `fragmentor`, логи в journald. Кода на сервере нет. — Конфиг остаётся «из env», пользователь бота не может прочитать файл с секретами, папки и права создаёт systemd.
- 2026-10-30 — systemd: `Restart=always`, `RestartSec=5`, автозапуск через `multi-user.target`; песочница (`ProtectSystem=strict`, без capabilities, только IPv4/IPv6/unix, `SystemCallFilter=@system-service` с `EPERM`, `MemoryDenyWriteExecute` и др.), писать можно только в папку базы и свой `/tmp`. — С шага 7 бот разбирает чужие файлы; оценка `systemd-analyze security` 1.4. Если новой функции нужна запись в другое место, её путь добавляется в юнит через `ReadWritePaths=`.
- 2026-10-30 — Сборка для сервера: `make build-linux` (`CGO_ENABLED=0`, `GOOS=linux`, `-trimpath -ldflags=-s`). Версия — коммит из информации о сборке, которую вшивает Go (`+dirty` при незакоммиченных изменениях), пишется первой строкой лога. — Бинарник не зависит от libc сервера, а по логу видно, какая версия работает.
- 2026-10-30 — Выкатка вручную по `bot/DEPLOY.md`: `scp` в домашнюю папку, предыдущий бинарник сохраняется как `.prev`, замена через `mv`, `systemctl restart`. Перед версией с новыми миграциями — копия `/var/lib/fragmentor` в `/var/backups`. — Откат за одну команду; старый бинарник на новой схеме не стартует, поэтому нужна копия базы.
- 2026-10-30 — Локально работает отдельный dev-бот: `TELEGRAM_DEV_BOT_TOKEN` важнее `TELEGRAM_BOT_TOKEN`, и тогда боевой токен не обязателен. Боевой токен есть только на сервере, на сервере dev-токен не задаётся. — Telegram отдаёт апдейты только одному процессу, а локальный запуск с боевым токеном мешал бы серверу (409 Conflict).
- 2026-10-30 — IP сервера не храним в репозитории, в инструкциях — SSH-алиас `fragmentor-vps`. — Репозиторий может стать публичным: код расширения открытый.
- 2026-10-30 — `.gitattributes`: `*.sh` и `*.service` всегда с LF. — На Windows включён `core.autocrlf`, а bash и systemd ломаются на CRLF.
- 2026-10-30 — Проверка Telegram с сервера: токен вводится через `read -s` и передаётся в `curl -K -` через stdin. — Токен не попадает ни в историю команд, ни в список процессов.
- 2026-11-02 — Сайт и почта — на хостинге AdminVPS, бот — на отдельном VPS за рубежом вместе с VPN (Xray в Docker; Ubuntu 24.04, 1 ГБ RAM). Docker и Xray не трогаем, бот портов не слушает. Порт 443 занят Xray — учтём на шаге 10 (HTTPS-эндпоинт для расширения). На шаге 4 по замеру пиковой памяти решаем, хватает ли 1 ГБ для парсинга демок. — AdminVPS — виртуальный хостинг без root и systemd, бота туда не поставить.
- 2026-11-02 — Лимиты памяти бота в юните: `GOMEMLIMIT=320MiB`, `MemoryHigh=380M`, `MemoryMax=400M`, `MemorySwapMax=128M`, `OOMScoreAdjust=1000`. Предварительные, пересматриваем на шаге 4. Задача, на которой бот падает по памяти, не должна повторяться бесконечно — учесть в очереди на шаге 7. — При нехватке памяти убивают бота, а не VPN. `MemoryMax` не учитывает swap, отсюда `MemorySwapMax`. `MemoryHigh` вплотную к `MemoryMax`: в WSL с порогом в 75% от лимита процесс завис под троттлингом больше чем на 90 с, с 94% и без порога убит за 4–6 с и перезапущен. Мягкий слой — `GOMEMLIMIT`, из cgroup Go 1.27 его сам не берёт.
- 2026-11-02 — На сервере swap-файл 2 ГБ и `vm.swappiness=10`. — На 1 ГБ RAM без swap любой всплеск памяти кончается OOM; низкий swappiness держит рабочую память VPN и бота в RAM, swap — только запас.
- 2026-11-02 — Вход по SSH только по ключу: `PasswordAuthentication no`, `KbdInteractiveAuthentication no`, `PermitRootLogin prohibit-password` в `/etc/ssh/sshd_config.d/00-keys-only.conf`; отключаем после проверки входа по ключу, не закрывая текущую сессию. — Пароли подбирают ботнеты. Префикс `00-`: sshd берёт первое значение настройки, а `50-cloud-init.conf` в образах Ubuntu может включать пароли.
- 2026-11-02 — Прокси для Telegram на сервере не нужен, `HTTPS_PROXY` не задаём. — Проверка `deploy/check-telegram.sh` с VPS: соединение с `api.telegram.org` ~2 мс, TLS ~30 мс, запрос целиком ~40 мс, `getMe` с боевым токеном 77 мс.
