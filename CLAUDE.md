# Fragmentor — инструкции для Claude Code

## О проекте

Fragmentor — ИИ-тренер по CS2 в Telegram (@fragmentor_ai_bot, сайт fragmentor.tech).
Игрок привязывает ник FACEIT, бот скачивает демку его матча, парсит её, считает метрики
и присылает короткий разбор: три главные ошибки и одно задание на неделю,
со сравнением с игроками того же уровня FACEIT.

- Аудитория: русскоязычные игроки FACEIT 5–8 уровня. Язык бота — русский,
  английский для пользователей с `language_code` не `ru`.
- Команда: один разработчик (kolyx) и Claude Code.
- Статус: ранняя разработка. Заявка на FACEIT Downloads API на паузе (FACEIT приостановил
  некоммерческие заявки), демки получаем по ссылке от пользователя и через расширение для браузера.

## Структура репозитория

- `bot/` — Telegram-бот на Go: весь серверный код продукта.
- `extension/` — расширение для Chrome (шаг 10).
- `landing/` — сайт fragmentor.tech. Правится только `landing/src/`,
  сборка `python3 landing/build.py` кладёт готовый сайт в `landing/dist/`,
  а `dist/` я заливаю на хостинг вручную.
- `docs/PLAN.md` — пошаговый план. Источник правды о том, что делаем и в каком порядке.
- `docs/METRICS.md` — точные определения всех метрик.
- `docs/FINDINGS.md` — правила находок: когда метрика становится ошибкой или сильной стороной.
- `docs/DECISIONS.md` — журнал принятых решений.
- `docs/notes/` — конспекты по внешним библиотекам и API.

## Как мы работаем — главное правило

1. Работаем строго по шагам из `docs/PLAN.md`. Я называю номер шага, ты делаешь только его.
2. Не начинай следующий шаг, даже если он кажется очевидным продолжением.
   Не переделывай код прошлых шагов без моего явного согласия.
3. Перед тем как писать код, прочитай описание шага, `docs/DECISIONS.md` и текущий код,
   предложи план и дождись моего согласия.
4. Если шаг требует отступить от зафиксированного решения или от определения метрики,
   остановись и спроси. Никаких молчаливых изменений.
5. Шаг закрыт, когда выполнены все пункты «Готово, когда», тесты проходят,
   а в `docs/PLAN.md` и `docs/DECISIONS.md` записано, что сделано и что решено.
6. Не коммить и не пушь сам: предложи текст коммита, коммичу я.
7. Общайся со мной по-русски. Код, имена и сообщения коммитов — на английском.

## Зафиксированные решения

- Go, последняя стабильная версия. Один Go-модуль в `bot/`.
- Telegram: `github.com/go-telegram/bot`, long polling. Если библиотека заброшена —
  не меняй молча, предложи замену и спроси.
- Парсер демок: `github.com/markus-wa/demoinfocs-golang/v6`. Стабильной v6 пока нет (ноябрь 2026),
  берём пре-релиз `v6.0.0-rc.1`, закреплённый точно; запасной вариант — стабильная `v5.2.0`.
  Весь код, который зависит от demoinfocs, — только в `internal/demo`. Когда выйдет `v6.0.0`,
  переходим на неё и заново прогоняем сверку `go run ./cmd/parsedemo -faceit testdata`.
- Демки FACEIT приходят как `.dem.zst`. Распаковка потоком через
  `github.com/klauspost/compress/zstd` прямо в парсер, распакованный файл на диск не пишем.
- Хранилище: SQLite через `modernc.org/sqlite` (без CGO). Миграции — SQL-файлы,
  встроенные через `embed`, с таблицей версии схемы. Каждый шаг добавляет свои таблицы
  новой миграцией, старые миграции не редактируем.
- Логи: `log/slog`. Конфиг: переменные окружения, локально — файл `bot/.env`.
- Очередь разборов: воркеры внутри процесса и таблица задач в SQLite,
  одновременно не больше двух разборов.
- FACEIT Data API: профиль игрока, история матчей, детали матча (уровни, SteamID64, `demo_url`).
- LLM: агрегатор polza.ai, модель DeepSeek V4.1 Flash. Адрес API, ключ и модель — из env.
- Все цифры считает код. LLM получает компактный JSON с фактами и только пишет текст.
  Каждое число в ответе LLM сверяется с JSON.
- В LLM не передаём ники, SteamID, Telegram ID и другие идентификаторы — только обезличенные цифры.
- Пользователь определяется по Telegram ID. FACEIT-аккаунт привязывается по нику
  или ссылке на профиль. Вход через Steam не делаем.
- Демка удаляется сразу после разбора при любом исходе. Хранится только посчитанное.

## Внешние библиотеки и API

- Прежде чем использовать внешнюю библиотеку или API, изучи их актуальную документацию,
  примеры и исходники. Не полагайся на память: интерфейсы могли измениться.
- Для Go-модулей используй `go doc` и исходники в кэше модулей после `go get`.
- Главное из изученного записывай в `docs/notes/<название>.md`: ключевые типы и функции,
  события и поля, подводные камни, ссылки на источники. В следующих шагах сначала читай эти заметки.

## Безопасность

- Никогда не читай, не открывай и не выводи `bot/.env` и любые другие секреты.
  Имена переменных смотри в `bot/.env.example`.
- Секреты не попадают в код, логи, тесты, фикстуры и сообщения коммитов.
- Демки скачиваем только с разрешённых хостов FACEIT, с лимитом размера и таймаутом.
- Тестовые демки лежат в `bot/testdata/` и не коммитятся.
- На сервер сам не ходи (ssh, scp и любые другие способы): команды на сервере выполняю я по `bot/DEPLOY.md`.
- `make deploy` (выкатка на сервер) запускаю только я. Не запускай её ни в каком виде, даже с `-n`
  или через `make -C`: запрет и в `.claude/settings.json`.

## Правила кода

- После каждого шага проходят `gofmt`, `go vet` и `go test ./...`.
- Ошибки оборачиваем с контекстом (`fmt.Errorf("load match: %w", err)`) и не глотаем.
- `context.Context` во всех внешних вызовах, у всех HTTP-запросов есть таймауты.
- Логика (парсинг, метрики, форматирование разбора) не зависит от Telegram и БД,
  чтобы её можно было тестировать отдельно.
- Формулы метрик покрыты юнит-тестами на синтетических данных.
- Все тексты для пользователя лежат в одном пакете локализации, на русском и английском.
  Исключение — каталоги в `bot/content/` (упражнения, словарь зон): их тексты на ru и en лежат
  рядом с данными, тест требует оба языка.
- Тесты не ходят в реальные API: только записанные ответы и `httptest`.
