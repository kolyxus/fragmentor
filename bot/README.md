# Fragmentor bot

Telegram-бот Fragmentor на Go. Сейчас умеет `/start` (запись в очередь на бету), `/link` (привязка
аккаунта FACEIT по нику или ссылке на профиль), `/matches` (последние 5 матчей CS2 со статистикой
и выбором часового пояса кнопкой под списком) и `/help`. Админы (`ADMIN_TELEGRAM_IDS`) могут прислать
ссылку на демку матча: бот скачает и разберёт её и сохранит метрики (раздел «Разбор по ссылке»).
Боевой бот @fragmentor_ai_bot работает на сервере, как его выкатывать — в [DEPLOY.md](DEPLOY.md).

## Запуск локально

Нужны Go 1.27+ и, по желанию, GNU make. Все команды — из папки `bot/`.

1. Скопировать шаблон настроек и вписать токен **dev-бота** (отдельный бот из BotFather)
   и ключ FACEIT Data API:
   ```
   cp .env.example .env        # Windows: copy .env.example .env
   ```
   Нужны `TELEGRAM_DEV_BOT_TOKEN` и `FACEIT_API_KEY`. Боевой токен локально не нужен:
   он хранится только на сервере.
2. Запустить:
   ```
   make run                    # или: go run ./cmd/bot
   ```
   В первой строке лога — `dev_bot=true`, ниже — ник dev-бота в `telegram bot authorized`.
3. Написать dev-боту `/start`, `/help`, `/link <ник>` и `/matches`. Язык ответа зависит
   от `language_code` пользователя: русский для `ru`, английский для всех остальных.

Остановка — Ctrl+C: бот перестаёт принимать сообщения, отвечает на начатые и закрывает базу.
Второй Ctrl+C завершает процесс сразу.

## Настройки

Читаются из переменных окружения, локально — из `.env` в текущей папке.
Переменные окружения важнее значений из файла.

| Переменная | По умолчанию | Что это |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | токен боевого бота, обязательна, если нет dev-токена |
| `TELEGRAM_DEV_BOT_TOKEN` | — | только локально: токен dev-бота, если задан — важнее `TELEGRAM_BOT_TOKEN` |
| `FACEIT_API_KEY` | — | server-side ключ FACEIT Data API (developers.faceit.com → App Studio), обязательна |
| `DATABASE_PATH` | `./data/fragmentor.db` | файл SQLite, папка создаётся сама |
| `LOG_LEVEL` | `info` | `debug`, `info`, `warn` или `error` |
| `ADMIN_TELEGRAM_IDS` | — | Telegram ID админов через запятую; до шага 12 только они присылают демки на разбор |
| `HTTPS_PROXY` | — | прокси для запросов к Telegram, FACEIT и хранилищу демок, если они недоступны |

Остальные переменные из `.env.example` понадобятся в следующих шагах.

## Команды make

| Цель | Что делает |
|---|---|
| `make run` | запускает бота |
| `make test` | `go test ./...` |
| `make lint` | падает, если файлам нужен `gofmt`, затем `go vet ./...` |
| `make build` | собирает `bin/fragmentor` (`bin/fragmentor.exe` на Windows) |
| `make build-linux` | статический бинарник для сервера `bin/fragmentor-linux-amd64` (`LINUX_ARCH=arm64` — под ARM) |
| `make deploy` | выкатка на сервер: проверки, сборка, бэкап базы, замена бинарника, перезапуск — раздел 4.1 [DEPLOY.md](DEPLOY.md); запускает только автор |

## База

SQLite создаётся при первом запуске, миграции из `internal/storage/migrations/` применяются сами.
Новая таблица — новый файл `NNNN_name.sql` со следующим номером; применённые файлы не редактируем.
Сбросить локальную базу — удалить папку `data/`.

## Фикстуры FACEIT

Тесты клиента FACEIT (`internal/faceit`) ходят не в FACEIT, а в `httptest` с записанными ответами
из `internal/faceit/testdata/`. Перезаписать их, если FACEIT поменял формат:

```
go run ./cmd/faceitrecord -nickname <ник> [-match <match_id>]...
```

Утилита берёт ключ из `.env`, заменяет ники, ID и SteamID подставными и не пишет файлы, если
что-то из настоящих значений осталось. Подробности — в `docs/notes/faceit-data-api.md`.

## Разбор демок

`cmd/parsedemo` разбирает демки FACEIT (`.dem.zst`) и печатает сводку матча в JSON: карту, раунды
со счётом, K/D/A, хедшоты и урон каждого игрока и метрики из `internal/metrics` — за матч и за каждую
сторону. Демки для проверки лежат в `testdata/` и в git не попадают.

```
go run ./cmd/parsedemo testdata                          # все демки из папки
go run ./cmd/parsedemo -events testdata/<демка>.dem.zst  # ещё и журнал: убийства, попадания, выстрелы, видимость, ослепления
go run ./cmd/parsedemo -faceit -json=false testdata      # сверка счёта, K/D/A и ADR с FACEIT
go run ./cmd/parsedemo -csda <папка> -json=false testdata # сверка метрик с cs-demo-analyzer
go run ./cmd/parsedemo -scope testdata/scope.json -json=false testdata # сверка стрельбы со Scope.gg
go run ./cmd/parsedemo -findings testdata testdata/3-4lvl testdata/7-8lvl > findings.txt # находки всех игроков
```

- С `-faceit` ID матча берётся из имени файла (`<match_id>-1-1.dem.zst`, как у FACEIT), ключ — из `.env`.
  Если счёт или K/D/A не совпали, утилита завершается с кодом 1; HS, урон и ADR — для справки, расхождение
  помечено `*`.
- С `-csda` в папке лежит JSON cs-demo-analyzer на каждую демку. Как его собрать и запустить и почему его
  цифры местами другие — `docs/notes/cs-demo-analyzer.md` и `docs/DECISIONS.md`. Расхождения с ним
  код выхода не меняют.
- С `-scope` в JSON-файле лежат цифры Scope.gg, переписанные со страниц матчей (формат — в
  `cmd/parsedemo/scope.go`, в файле ники, поэтому он в `testdata/` и в git не попадает). Утилита печатает
  наши и их цифры по каждому игроку и в конце корреляцию по всем демкам. Расхождения код выхода не меняют.
  Что совпадает и почему — `docs/notes/scope-gg.md`.
- С `-findings` вместо JSON печатаются находки из `internal/findings` (правила — `docs/FINDINGS.md`): для каждого
  игрока каждой демки — меры рядом с лобби, тиммейтами и соперниками, сработавшие правила с весами
  и доказательствами (раунд, часы, зона, `demo_gototick`) и то, что попало бы в разбор; в конце — сводка
  по правилам: у скольких игроков сработало каждое и сколько весят его находки. Своё среднее игрока — его
  остальные демки этого запуска, поэтому папки лучше давать все сразу. Папка — это её `*.zst`, без вложенных.
- Сводку, где раунды не сходятся со счётом или с подсчётом игры, утилита помечает `SUSPICIOUS`
  и тоже выходит с кодом 1; причины — в `warnings` (правило — в `docs/METRICS.md`).
- Время разбора и пиковая память печатаются в stderr; остальные флаги — `-h`.
- В выводе ники и SteamID — его не коммитим.

`make test` разбирает и демки из `testdata/` и её папок: тест `internal/demo` по одной, тесты `internal/metrics`
и `internal/findings` все сразу; с 13 демками это ~1,5–2 мин. `go test -short ./...` эти тесты пропускает. С `-race` разбор в 10–20 раз медленнее:
`go test -race -timeout 30m ./...` идёт около 12 минут. Как устроен разбор — в `docs/notes/demoinfocs.md`,
формулы метрик — в `docs/METRICS.md`.

## Разбор по ссылке

Админ присылает боту подписанную ссылку на демку из загрузок браузера (как её достать — кнопка
«Как достать ссылку» под `/help` у админов, подробности — `docs/notes/faceit-demo-links.md`). Остальным бот
отвечает, что разборы откроются с бетой. Код — `internal/analysis`, без Telegram:

- `Submit` проверяет ссылку и матч и ставит задачу в таблицу `jobs`:
  - ссылка не протухла;
  - аккаунт FACEIT привязан, матч закончен, на одной карте, пользователь в составе;
  - у пользователя нет этой демки в очереди и в очереди не больше трёх его демок.

  Если по оценке очереди ссылка не доживёт до своей очереди, задача не создаётся, а бот говорит, сколько ждать.
- Два воркера в процессе бота берут задачи по порядку. Демка идёт из сети через zstd прямо в парсер, на диск
  не пишется. Метрики считает `internal/metrics`.
- Хранится только посчитанное:
  - `matches` — матч;
  - `match_players` — метрики с ID только тех игроков, чей аккаунт FACEIT привязан в боте;
  - `reference_samples` — обезличенные метрики всех игроков для эталонов уровней, без ID, без ID матча
    и без времени.
- Статус («в очереди, место N», «разбираю», «готово» или причина ошибки) — одно сообщение, его правит
  одна горутина бота (`internal/telegram/status.go`).
- После падения бота задачи «в работе» возвращаются в очередь; задача, на которой бот упал дважды, проваливается.
  При остановке (Ctrl+C, выкатка) начатые разборы возвращаются в очередь без траты попытки.

Тест `internal/analysis` на демке из `testdata/` (без `-short`) проходит весь путь — скачивание с тестового
сервера, разбор, база — за ~3 с.

## Подводные камни

- Один токен — один запущенный бот. Второй процесс с тем же токеном получает от Telegram
  `409 Conflict`, и они мешают друг другу. Поэтому локально работаем только с dev-ботом
  (`TELEGRAM_DEV_BOT_TOKEN`), а боевой токен есть только на сервере.
- Команды меню и описания бот регистрирует сам при запуске, руками в BotFather их задавать не нужно:
  ручные правки перезапишутся.
