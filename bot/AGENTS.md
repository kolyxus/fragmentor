# Go-модуль бота

## Границы реализации

- Один модуль на последней стабильной версии Go. Минимальная версия Go и версии зависимостей указаны в [go.mod](go.mod). Для внешних пакетов сверяй интерфейсы через `go doc` и исходники в кэше модулей. Замену библиотеки, в том числе Telegram-клиента, согласуй с владельцем.
- Telegram работает через long polling. Пользователя определяем по Telegram ID, профиль FACEIT привязываем по нику или ссылке, без входа через Steam. Парсинг, расчёты и форматирование разбора изолированы от Telegram и БД. Настройки берём из окружения, логи пишем через `log/slog`.
- Зависимость от demoinfocs держи внутри `internal/demo`. Версия закреплена точно. Порядок перехода на стабильную v6 и запасная версия описаны в [конспекте парсера](../docs/notes/demoinfocs.md). Демки скачивай с разрешённых хостов FACEIT с лимитом размера и таймаутом. Распаковывай zstd потоком в парсер. Распакованный файл на диск не пишется, исходная демка удаляется после разбора при любом исходе.
- SQLite без CGO. Существующие SQL-миграции не редактируй. Каждое изменение схемы вноси новой встроенной миграцией. Очередь хранится в SQLite, одновременно выполняются до двух разборов внутри процесса. Для хранения журналов, метрик участников и фактов пользователя см. [решение от 2026-11-09 и его уточнения](../docs/DECISIONS.md).
- Для интеграции LLM используй согласованные провайдер и модель из журнала решений, адрес, ключ и модель — из окружения. Код вычисляет все числа. LLM формулирует текст по компактному JSON без ников и идентификаторов, каждое число ответа сверяется с фактами.
- Оборачивай ошибки с контекстом (`%w`), обрабатывай их. Внешние вызовы принимают `context.Context`, у HTTP-запросов есть таймауты. Тексты интерфейса — в пакете локализации на ru и en. Язык по умолчанию — английский, для русского языка пользователя — русский. В каталогах упражнений и зон переводы лежат рядом с данными в `content/`, тесты требуют оба языка.

## Проверки

- В конце шага из `bot/` проверь `gofmt`, `go vet ./...` и `go test ./...`. Цели `make lint` и `make test` выполняют эти проверки. Формулы проверяй на синтетических данных, внешние API — через записанные обезличенные ответы и `httptest`.
- Дополнительные проверки определяются шагом и [README](README.md). После обновления demoinfocs и перед выкатом требуется отдельная сверка `make verify-demos` с FACEIT. Если она требует закрытый файл с ключом, результат предоставляет владелец. Отмечай пропущенные проверки и отсутствие нужных демок. Личные демки и материалы в [testdata/](testdata/README.md) остаются вне Git.
