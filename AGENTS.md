# Fragmentor

Fragmentor — Telegram-тренер по матчам CS2 на FACEIT. Код рассчитывает игровые показатели и выбирает доказательства для короткого разбора с заданием на неделю. С владельцем общаемся по-русски. Код, имена и предлагаемые сообщения коммитов пишем по-английски.

## С чего начать

- [План](docs/PLAN.md) задаёт порядок шагов, статусы, критерии приёмки и точку продолжения. Для работы над шагом используй [навык `$step`](.agents/skills/step/SKILL.md). Начни с заголовков шагов и хода активного шага. Сопоставь их с рабочей копией и последними решениями по теме.
- [Решения](docs/DECISIONS.md) ищи по теме и дате, включая более поздние пересмотры. [Метрики](docs/METRICS.md) задают формулы, [находки](docs/FINDINGS.md) — условия, вес и доказательства игрового вывода. Перед обращением к внешней библиотеке или API прочитай соответствующий [конспект](docs/notes/), сверь его с актуальной документацией, примерами и исходниками. Новые проверенные особенности допиши туда же.
- Перед работой в `bot/` прочитай [инструкции Go-модуля](bot/AGENTS.md), в том числе при старте из корня. Для сайта правь только `landing/src/`. Команда сборки из корня — `python3 landing/build.py`, содержимое `landing/dist/` загружает владелец.
- Постоянные инструкции Codex находятся в `AGENTS.md` соответствующей области. [PROJECT.md](PROJECT.md) хранит оригинал инструкций Claude для прежнего процесса.

## Границы работы

- Один шаг — одна сессия. До изменения кода согласуй с владельцем план выбранного шага. Перед переделкой кода прошлого шага, отступлением от решения или изменением формулы требуется его явное согласие. Сохраняй чужие незакоммиченные изменения.
- Шаг закрывается после выполнения всех «Готово, когда», обязательных проверок, явной приёмки владельцем там, где она требуется, и записи результата на диске. Для следующего шага владелец открывает чистую сессию. Коммит и push делает владелец.
- Основной агент отвечает за границы задачи, координацию и итог. Вызывай специалистов по необходимости. `tech-lead` — самостоятельный субагент для требований и плана, `architect` — для архитектуры, `developer` — для реализации, `qa-engineer` — для тестов, `reviewer` — для независимой проверки существенных изменений, `devops-engineer` — для работ с инфраструктурой в пределах поручения. Для углублённого аудита и объёмной документации доступны навыки `$security-audit` и `$technical-documentation`.

## Доступ и публикация

- Эти границы действуют для основного агента и каждого субагента, включая `devops-engineer`. Не открывай, не считывай и не выводи секреты, файлы `.env`, `.env.local`, `.env.production` и хранилища учётных данных. Имена настроек бери из [шаблона](bot/.env.example). Секретам нет места в коде, логах, тестах, фикстурах и сообщениях коммитов.
- Доступ к серверу любым способом, публикация и выкат принадлежат владельцу. Агентам запрещены SSH, SCP и любой вызов цели `deploy`, включая `make -n deploy` и `make -C bot deploy`. [Инструкция владельца](bot/DEPLOY.md).
- Не обходи запреты через другую команду, оболочку, инструмент, повышение прав или делегацию. Границы выше действуют при любом профиле. [Командные правила](.codex/rules/fragmentor.rules) проверяют распознанные префиксы команд агента. Отдельный API-вызов `command/exec` может исполнить команду с таким префиксом.
- [Профиль fragmentor](.codex/config.toml) рассчитан на локальный `:workspace` и добавляет запреты чтения. В Windows шаблоны охватывают файлы, существующие на старте процесса, в пределах заданной глубины. Открытый чат или другой клиент может сохранить иной профиль. Проектный выбор по умолчанию имеет приоритет над личным. Если на машине действуют более строгие ограничения, владелец явно выбирает свой профиль с сохранением этих ограничений. Самостоятельно переключать права агентам запрещено.
